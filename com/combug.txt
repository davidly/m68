Issue with a much oder COM.68K now named ORIGCOM.68K in this repo.

com.68k fails to run binaries created by C Vers. 1.06D 8080  (C) 1982 1983 1984 by Manx Software Systems.

That's because com.68k doesn't set the Parity bit correctly for the ADI instruction. 

Code from asave.asm in the Manx c runtime to save ix/iy on the Z80 uses the behavior of the parity flag after an ADI instruction to distinguish 8080 from Z80.

    .asave:         ;support for assembly routines which must save IX and IY
            pop     d               ;save return address
            lxi     h,2             ;compute address of arguments
            dad     sp
            xra     a
            adi     3
            jpe     nopush          ; <===============  jump past push if an 8080, not a Z80
            DB 221,229,253,229      ;push ix ; push iy
    nopush:

-------------------------------------------
should work like this on an 8080: partity is even for the adi

    pc 1582, op af, op2 c6, op3 03, a 00, B 007f, D 18e6, H 0081, sp feea, SzaPC, xra a
    pc 1583, op c6, op2 03, op3 ea, a 00, B 007f, D 18e6, H 0081, sp feea, sZaPc, adi 03h
    pc 1585, op ea, op2 8c, op3 15, a 03, B 007f, D 18e6, H 0081, sp feea, szaPc, jpe 158ch
    pc 158c, op 7e, op2 12, op3 13, a 03, B 007f, D 18e6, H 0081, sp feea, szaPc, mov a, m

-------------------------------------------
